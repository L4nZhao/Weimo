---
name: create-skill
description: 创建或更新项目内置 Skill。仅当用户要沉淀长期反复使用、跨主题/跨场景的稳定工作流时使用；不要为单个知识主题、报告主题、介绍文章或一次性问答创建 Skill。
---

当用户要求创建新技能时，先判断它是否真的是可复用工作流。只有通过判断时，才调用 `create_skill`。

可以创建 Skill 的情况：
- 需求是稳定流程，而不是单个内容主题。
- 未来会反复使用，且适用于多个主题、多个文件、多个用户请求或多个场景。
- 具有明确输入、输出、步骤、触发条件、不触发条件和安全边界。
- 不能直接由现有 Skill、知识库、媒体检索、文档生成或普通对话组合完成。

不要创建 Skill 的情况：
- 用户只是让机器人写一份报告、介绍、文章、方案、总结或 Word 文档。
- 用户只是询问某个知识点、游戏、产品、新闻、皮肤、趋势或资料。
- 用户只是要求联网查询、实时信息、普通聊天或一次性任务。
- 需求应进入知识库、记忆或文档生成上下文，而不是能力层。

整理可复用 Skill 时：
- `name` 使用英文小写短横线命名，描述通用工作流，不要使用 `某主题-report`、`某主题-summary` 这类主题型名称。
- `description` 写清技能做什么、哪些请求应该触发、哪些请求不应该触发。
- `instructions` 写给 AI Agent 使用，保留输入、输出、流程、约束、示例和安全边界；不要写无关背景。

默认创建提示型 Skill。创建后系统会自动生成一个 `use_<skill>` 工具，后续 Agent 可通过该工具加载技能指令。

安全要求：
- 只能创建自然语言提示型 Skill，不能创建会执行代码、Shell 命令、读取文件、读取环境变量或访问系统密钥的 Skill。
- 不得要求泄露、读取、发送或上传用户隐私、项目私密数据、Cookie、Session、Token、API Key、密码、私钥等信息。
- 不得包含破坏性文件、数据库或系统操作。
- 如果需求不安全，拒绝创建，并说明需要改成安全的提示型流程。

只有当用户明确要求覆盖已有技能时，才设置 `overwrite=true`。
